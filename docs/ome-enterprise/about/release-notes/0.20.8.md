## 0.20.8.0 (June 25, 2026)

### OvenMediaEngine

#### \[Compatibility]

* Compatible with the `Server.xml` configuration format used in version 0.12.6 or later.
* Compatible with Origin and Edge versions 0.20.8.0 or later.

#### \[Added]

* Added RTX (NACK-based packet retransmission) support in the WebRTC Provider. Enable via the `<Rtx><Enable>true</Enable></Rtx>` option under the application's WebRTC settings to reduce visible artifacts on lossy networks.
* Added `TrackPrepareTimeout` rule to Anomaly Detection. Detects when a negotiated track (for example a Simulcast layer the client never sends) stays unready while other tracks keep arriving, and can terminate the stream or send an alert. Configure via `<TrackPrepareTimeout>` under `<Alert><Rules><Anomaly>`.
  * [Go to guide](https://ovenmedialabs.com/docs/ome-enterprise/features/operations-and-monitoring/enhanced-alert#configuring-trackpreparetimeout)
* Added a Recording Files page to the Web Console. Browse all completed recordings in one place, and download or delete individual files directly from the browser.
  * [Go to guide](https://ovenmedialabs.com/docs/ome-enterprise/exclusive/web-console/web-console-overview/recording-files)

#### \[Fixed]

* Fixed an issue where the transcoded output framerate was set to twice the source framerate when an NVIDIA hardware decoder was used and no explicit output framerate was configured. This is an Enterprise-only fix.
* Fixed incorrect configuration validation logic in the Anomaly Detection rules. A misconfigured `Count=0` value and an empty `<Action>` tag were not handled correctly, which could lead to unexpected behavior during rule evaluation.
* Fixed an intermittent crash (SIGABRT) that could occur when the HAProxy protocol was enabled and only partial data was received on a connection.
* Fixed a crash that occurred when a stream using the Whisper STT feature was stopped while STT was disabled in the configuration.
* Fixed an LLHLS playback issue where Safari would stall or disconnect shortly after starting. The problem was most visible over plain HTTP but could also occur intermittently over HTTPS.
* Fixed Push session error logs showing a blank `Reason` field when an outbound push connection failed.
* Added a warning log when a stream track does not receive valid media for an extended period, making it easier to diagnose why a stream is stuck in the initializing state.

#### \[Improved]

* Higher concurrent WebRTC ingest capacity. UDP traffic is now spread across multiple worker sockets, reducing CPU bottlenecks at high connection counts. Enable via the `<IceWorkerCount>` setting in the WebRTC provider configuration.
* Improved WebRTC playback smoothness at startup. The jitter buffer now calibrates its baseline per track and uses asymmetric delay smoothing, reducing stutter visible to viewers immediately after a publisher connects.
* Stream track information (codec, bitstream format, sample rate, etc.) is now printed to the log at stream creation time, not just at the prepared state. This makes it easier to diagnose streams that fail to reach the prepared state.
